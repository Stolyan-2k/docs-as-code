## Связь с моделью

Авторы [SafeTechDev/Russian-Spam-classifier](model-card.md) называют этот датасет
**внешним оценочным**, не пересекающимся с их обучающей выборкой.
Это заявление авторов модели, а не результат нашей проверки данных.
Несмотря на название split `train`, для выбранной модели источник описывает
применение набора именно для оценки. Набор нельзя автоматически считать
обучающей выборкой этой модели.

## Состав данных

**Объём:** 21 411 примеров в единственном объявленном split `train`.
Метаданные указывают `dataset_size: 4652352` байта и `download_size: 2266992` байта.
Самостоятельные `validation` и `test` в карточке не объявлены.

**Тип данных:** текстовые сообщения с меткой бинарной классификации.

**Основные поля / признаки:**

| Поле | Тип | Значение |
| --- | --- | --- |
| `text` | `string` | Текст сообщения. |
| `label` | `ClassLabel` | `0`: `not_spam`; `1`: `spam`. |

Для нашего API `not_spam` соответствует `ham`, а `spam` — `spam`.
Доли классов, распределение длин, количество уникальных авторов, чатов и дубликатов
в изученной карточке **не указаны**. Полный набор не скачивался и не анализировался;
21 411 — объём из метаданных, а не результат собственного подсчёта.

## Получение данных

Название и тематическая направленность карточки связывают набор с Telegram-спамом.
Точный способ сбора сообщений, источники чатов, даты сбора, критерии включения,
согласие авторов сообщений и процедура разметки **не указаны**.
Не следует переносить описание сбора обучающих данных SafeTechDev на этот набор:
это разные источники данных.

## Предобработка

В изученной карточке датасета сведения об очистке, удалении дубликатов,
обезличивании, нормализации и проверке согласованности разметки **не указаны**.
Нормализация из карточки модели относится к её обучению и использованию,
а не является подтверждённой предобработкой опубликованного набора.

**Предлагаемая процедура для нашего проекта, ещё не выполненная:** проверить
пустые тексты, метки и длины; выявить дубликаты; проверить наличие персональных
данных; зафиксировать версию нормализации. При создании локальных выборок нужно
избегать попадания дубликатов в разные части и не подбирать пороги на финальном тесте.
Если метаданных чата, автора или времени нет, разбиение по этим признакам
без дополнительного источника выполнить нельзя.

## Ограничения

1. Наличие только split `train` не предоставляет готового независимого тестового протокола.
2. Неизвестный баланс классов не позволяет заранее оценить репрезентативность по одной общей метрике.
3. Недостаточно сведений о сборе, согласии, обезличивании и разметке для полного аудита качества и приватности.
4. **Потенциальное ограничение для нашего проекта:** Telegram-сообщения могут отличаться от текстов нашего сообщества по лексике, длине и типам спама; переносимость требует проверки.
5. **Потенциальное ограничение для нашего проекта:** повторение оценки на известном автору модели наборе не заменяет независимый тест на новых данных.

## Использование в проекте

Набор подходит как открытый кандидат для предварительной проверки бинарной
классификации и адаптера меток. Его связь с выбранной моделью подтверждена
карточкой модели, но качество в нашем проекте ещё не измерялось.

Перед внедрением планируется оценить precision, recall и F1 для спама, матрицу
ошибок и отдельно ложные срабатывания на обычных сообщениях. Нужны срезы
по длине, языку и тематике, а также отдельная выборка целевого сообщества
с допустимым основанием обработки. Это план, а не выполненный эксперимент.
