## Использование в проекте

**Проектное решение:** модель могла бы выполнять роль ML-компонента в
[диаграмме последовательности UC-01](../project/diagrams.md).
Модератор вызывает `POST /classifications`; приложение проверяет длину текста,
передаёт сообщение модели и сохраняет результат. `GET /classifications/{id}`
возвращает результат, а `POST /classifications/{id}/feedback` сохраняет исправление
модератора без изменения исходной категории. См. [спецификацию API](../api/index.md).

Планируемое преобразование ответа модели в контракт API:

- `SPAM` преобразуется в `spam`, `SAFE` — в `ham`.
- Модель выдаёт логит; после `sigmoid` получается оценка `prob_spam`.
  Для `spam` поле `confidence` равно `prob_spam`, для `ham` — `1 - prob_spam`.
  Это оценка модели, а не доказанная калиброванная вероятность правильности.
- В примере авторов порог категории — `prob_spam >= 0.7` для `SPAM`.
  Это отдельный порог от правила нашего API: `manualReviewRequired = confidence < 0.8`.
  Например, при `prob_spam = 0.75` категория — `spam`, но нужна ручная проверка.
  Оба порога необходимо оценить на данных нашего сообщества до внедрения.
- `modelVersion` должно идентифицировать закреплённую ревизию модели и версию
  предобработки; `id`, `messageId`, `moderatorId` и время создаёт приложение,
  а не нейросеть. `spam-ru-1.0.0` в API — учебный пример, а не имя этой модели.

Предварительный выбор модели не меняет контракт API и не означает готовности
сервиса. Особенно важно до реализации решить проблему усечения длинных текстов.

## Входные данные

**По карточке авторов:** отдельное русскоязычное текстовое сообщение.
Токенизатор формирует `input_ids` и `attention_mask`. В `config.json`
параметр `max_length` равен **40**; пример использует усечение и дополнение
до этой длины. Токены не равны символам.

Авторы рекомендуют нормализацию, применявшуюся при обучении: устранение
разрежённого написания, замену гомоглифов, удаление ссылок и команд ботов,
схлопывание повторяющихся букв и приведение к нижнему регистру.
Полная реализация этой нормализации в изученной карточке не приведена.

**Для нашего проекта:** API принимает 1–5000 символов после удаления пробелов
по краям. Такой текст может превысить 40 токенов; допустимость запроса по API
не означает, что модель проанализирует его целиком. Стратегию обработки длинных
сообщений и нормализацию нужно реализовать и проверить отдельно.

## Выходные данные

**По карточке авторов:** один логит, преобразуемый `sigmoid` в `prob_spam`;
пример возвращает объект с `label` (`SPAM`/`SAFE`) и `prob_spam`.
Модель не возвращает объяснение решения, идентификатор результата или автора проверки.

## Метрики качества

По карточке авторов, на внешнем `alt-gnome/telegram-spam` получены:

| Метрика | Заявленное значение |
| --- | --- |
| F1 | 0.96 |
| Precision | 0.99 |
| Recall | 0.93 |

Это результаты авторов, не наши измерения. Размер фактически использованной
оценочной подвыборки, доверительные интервалы, схема усреднения и воспроизводимый
протокол расчёта метрик не указаны авторами модели. Precision 0.99 не означает,
что доля ложных срабатываний среди всех обычных сообщений равна 1 %.
Качество на сообщениях нашего сообщества ещё не измерено.

## Ограничения

### Указанные авторами

1. Модель обучена и валидирована на русском языке; качество на других языках не гарантируется.
2. Модель классифицирует отдельное сообщение и не учитывает контекст переписки.
3. Порог 0.7 нужно подбирать под целевые данные: баланс precision/recall зависит от домена.
4. Из-за кастомной головы модель не запускается напрямую стандартным `transformers.pipeline("text-classification", ...)`; требуется описанный авторами загрузчик.

### Анализ для нашего проекта

- **Потенциальное ограничение для нашего проекта:** при лимите 40 токенов из примера авторов спам-признак в конце длинного сообщения может потеряться. Нужно сравнить стратегии обработки длинных текстов до внедрения.
- **Потенциальное ограничение для нашего проекта:** нормализация может удалить полезные признаки ссылок или изменить смысл; полную процедуру необходимо зафиксировать и проверить на пограничных примерах.
- **Потенциальное ограничение для нашего проекта:** новые схемы спама, сленг и тексты другого сообщества могут отличаться от оценочных данных. Нужна отдельная проверка качества и регулярный мониторинг.

## Не рекомендуется использовать

Не применять как единственное основание для автоматического удаления сообщений
или блокировки людей. Не считать результат доказательством мошенничества.
Без отдельной оценки не использовать для других языков, вложений, анализа
диалога целиком или длинных текстов с непроверенной стратегией усечения.
Наш проект оставляет решение модератору и позволяет сохранить исправление.
