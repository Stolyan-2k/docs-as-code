# API системы определения спама

API предоставляет доступ к проверке русскоязычных сообщений и обратной связи
модератора. Контракт соответствует [требованиям практики 2](../project/requirements.md).
Backend в этой работе не реализован. Адрес `https://example.com/api/v1` условный.

## Основные операции

| Метод и путь | Назначение | Требования |
| --- | --- | --- |
| `POST /classifications` | Проверить текст и сохранить результат ML-модели | US-01, US-02, UC-01 |
| `GET /classifications/{id}` | Получить сохранённый результат по положительному целому `id` | US-02 |
| `POST /classifications/{id}/feedback` | Сохранить исправленную категорию, не меняя исходный ответ модели | US-03 |

В проектируемом API модератор определяется по Bearer-токену, а не по переданному
клиентом идентификатору. Выдача токенов вне области этой работы; реальные токены
для просмотра документации не нужны. Чужие результаты не раскрываются: API отвечает `404`.

## Спецификация и Swagger

- [Открыть Swagger UI](swagger.html) — операции, запросы, ответы и переиспользуемые схемы.
- [Спецификация OpenAPI 3.0.3](openapi.yaml) — исходный YAML для просмотра или импорта в Swagger Editor.

Swagger UI 5.17.14 и его стили сохранены в репозитории с лицензией Apache-2.0.
Просмотр работает без CDN. Откройте страницу через локальный сервер MkDocs,
раскройте нужную операцию и просмотрите `Request body` и `Responses`.
Отправка запросов (`Try it out`) отключена, поскольку реального API нет.
Внешний онлайн-валидатор также отключён; проверка спецификации выполняется локально.

## Проверка основной операции по Swagger UI

| Вопрос | Ответ для `POST /classifications` |
| --- | --- |
| Какой метод используется? | `POST` с телом `application/json`. |
| Какие данные передаются? | Объект с единственным обязательным полем `text`, строкой длиной 1–5000 символов после удаления пробельных символов по краям. Пустая строка и строка только из пробелов недопустимы. |
| Что обязательно? | Тело запроса, поле `text` и Bearer-авторизация проектируемого API. |
| Что возвращается при успехе? | `201`: `id`, `messageId`, `moderatorId`, `category`, `confidence`, `modelVersion`, `manualReviewRequired`, `checkedAt`. |
| Какие ошибки возможны? | `400` — некорректный запрос; `401` — нет авторизации; `502` — некорректный ответ модели; `503` — модель недоступна; `504` — тайм-аут модели; `500` — ошибка хранения. Все возвращают объект с `code` и `message`. |

### Пример запроса

```json
{
  "text": "Поздравляем! Вы выиграли приз, срочно переведите комиссию."
}
```

### Пример успешного ответа (201)

```json
{
  "id": 123,
  "messageId": 45,
  "moderatorId": 7,
  "category": "spam",
  "confidence": 0.94,
  "modelVersion": "spam-ru-1.0.0",
  "manualReviewRequired": false,
  "checkedAt": "2026-11-06T10:00:00Z"
}
```

`confidence` хранится от 0 до 1 и отображается интерфейсом в процентах.
При значении ниже `0.8` флаг `manualReviewRequired` равен `true`, иначе `false`.
Это проектный порог, а не измеренная гарантия качества. Ошибка модели не заменяется
выдуманной категорией. При ошибке хранения успешная запись не подтверждается.

Для обратной связи нужно передать `correctedCategory`: `spam` или `ham`,
отличающуюся от исходного ответа. Иначе API вернёт `409 CATEGORY_UNCHANGED`.
Исходный ответ остаётся неизменным; каждая запись обратной связи хранит своего автора.

## Воспроизводимая проверка

Из корня репозитория в активированном виртуальном окружении:

```bash
python -m pip install -r requirements-dev.txt
python -m openapi_spec_validator docs/api/openapi.yaml
mkdocs build --strict
mkdocs serve
```

Примеры в спецификации являются учебными данными. Скриншот проверенного Swagger UI
находится в `screenshots/practice-3-swagger.png` в корне репозитория.
